# adrobot

Обёртка над Keitaro: бэкенд в `backend/`, фронтенд в `frontend/`. Две части: создатель кампании и редактор потоков существующей кампании. Фронт один на обе, маршруты: `/` создатель, `/campaigns/:keitaroId` редактор.

## Запуск бэкенда

```bash
cd backend
cp .env.example .env   # заполнить KEITARO_API_TOKEN

uv sync
docker compose up --build
```

При старте контейнера `app` запускается только uvicorn, миграции автоматически не применяются. После `docker compose up` примените их вручную: `docker compose exec app alembic upgrade head`.

Бэкенд доступен на хосте на порту 8012 (в compose `8012:8000`) по умолчанию. Если этот порт занят, замените левую часть в `ports` на свой и укажите тот же адрес во фронте через `VITE_API_URL`.

После правок кода, в том числе в `alembic/`, образ нужно пересобрать: `docker compose up -d --build app`.

## Запуск фронтенда

```bash
cd frontend
docker compose up --build
```

Vite dev-сервер доступен на http://localhost:5173.

## Структура бэкенда

- `app/api`: маршруты (`routes.py`), зависимости FastAPI (`deps.py`), обработчики ошибок (`errors.py`)
- `app/core`: настройки, база, клиент Keitaro, логирование
- `app/models.py`: модели SQLAlchemy
- `app/repositories`: доступ к БД
- `app/schemas`: схемы запросов и ответов
- `app/services`: `campaign_creator.py` (создание кампании), `stream_editor.py` (редактор потоков), `offer.py` (офферы), `exceptions.py` (исключения сервисов)

## Миграции

В репозитории лежит одна начальная ревизия в `backend/alembic/versions`, созданная через autogenerate по итоговым моделям.

```bash
cd backend
uv run alembic upgrade head          # применить локально, без Docker

uv run alembic revision --autogenerate -m "описание"  # новая миграция
```

## Тесты и линтер

```bash
cd backend
uv run ruff check .
uv run ruff format --check .
uv run mypy .
uv run pytest
```

Интеграционные тесты репозиториев выполняются на локальной БД из compose (сервис `db`, `DATABASE_URL` из `.env`).

Тесты используют подмену клиента Keitaro (`FakeKeitaro` в `tests/conftest.py`).

## Переменные окружения

Бэкенд (см. backend/.env.example):

- `KEITARO_API_URL` — базовый URL API Keitaro
- `KEITARO_API_TOKEN` — API Token Keitaro (только на сервере)
- `DATABASE_URL` — строка подключения к PostgreSQL
- `GROUP_ID` — ID группы кампаний (10332, FORTESTS)
- `LOG_LEVEL` — уровень логирования

Фронтенд (если не заданы, используются значения по умолчанию):

- `VITE_API_URL` — адрес бэкенда, по умолчанию http://localhost:8012
- `VITE_KEITARO_URL` — адрес Keitaro для кнопки VIEW IN KT, по умолчанию https://tlgk.host

# Отчёт по тестовому заданию

## Как поняли ТЗ

Создатель. Форма из трёх полей (название, страна, оффер). Бэкенд проверяет данные и записывает в локальную БД кампанию со статусом `pending`, два потока («Google GEO» и «Selected Offer») и привязку оффера. Затем по шагам создаёт в Keitaro кампанию и оба потока: Google GEO (тип forced, фильтр по стране, редирект на google.com) и Selected Offer (тип default, схема `landings`, оффер с долей 100). Если всё прошло, кампания получает статус `synced`. При сбое на любом шаге созданное в Keitaro удаляется, кампания получает статус `failed` и текст ошибки в `last_error`, а клиенту возвращается ошибка по шагам с текстом Keitaro без изменений. Форму можно отправить заново.

Редактор (по тексту видео задания). Нужен слой между пользователем и Keitaro:

- Fetch Streams: потоки кампании из Keitaro попадают в нашу БД. Потоки без офферов сохраняются в нашей БД, но не обрабатываются. Кампании, подтянутые из Keitaro, сохраняются со статусом `synced`, редактор находит кампании только с этим статусом.
- Add, Remove, Bring Back, Pin и пересчёт долей меняют только нашу БД: правки накапливаются у нас и уходят в Keitaro только по Push to KT. Поток с неопубликованными правками жёлтый.
- Push to KT публикует поток в Keitaro. Возможен только при сумме долей активных офферов 100%. Cancel возвращает поток к состоянию Keitaro.
- Удалённый оффер серый с долей 0%, после Push он остаётся у нас в архиве, Bring Back возвращает его.
- Оффер, удалённый в самом Keitaro, после Fetch становится серым (Removed), как будто удалён в нашем редакторе.
- Pin фиксирует долю: закреплённые доли при пересчёте не меняются, остаток делится поровну между остальными, лишний процент достаётся первому по порядку.

## Что сделано

- Бэкенд создателя и редактора: FastAPI, async SQLAlchemy, Alembic, репозитории и сервисы, обработка ошибок по шагам.
- Фронтенд создателя и редактора: React, TypeScript, Vite, react-router-dom, чистый CSS.
- Редактор показывает фильтры потока и клики за сегодня (по Fetch), есть ссылка VIEW IN KT.

## Сомнительные места и затруднения

- Права токена в Keitaro: виден один оффер (18813), список источников трафика пуст, создать оффер нельзя (  "error": "You have no permission to access this page - Offers"). ТЗ ожидает ровно один источник трафика, иначе ошибку; здесь при пустом списке `traffic_source_id` равен 0, как у существующей кампании в Keitaro.
- У потоков без офферов нет формы ADD: добавлять офферы в такой поток нельзя. В видео задания такой случай не показан, поэтому поток отображается только заголовком (название, фильтр, ID потока, клики за сегодня).

## Как тестировали редактор

У тестового токена в Keitaro виден один оффер (18813), поэтому в потоке всегда один оффер. На живых данных нельзя было проверить ADD, пин и пересчёт долей. Чтобы имитировать добавление новых офферов, я завёл в БД через SQL (psql) тестовые офферы 900001-900003 и их неопубликованные связи с потоком. Остальное проверял вручную:

- На кампании, загруженной из Keitaro: Fetch, отображение фильтров и кликов, Remove, Push после Remove, повторное добавление того же оффера (ADD через интерфейс), Push после Add, Remove и Cancel, Bring Back, нажатие пина.

- На кампании, созданной через мой создатель кампаний: Remove, Bring Back и Cancel с несколькими офферами, а также пин (закреплённая доля 34% не менялась, остальные пересчитывались). Ещё Fetch после удаления оффера в Keitaro: оффер стал серым, 0%, Removed.

- Страница незагруженной кампании показывает красную ошибку «Кампания не загружена, сначала Fetch Streams» и пустую таблицу.
