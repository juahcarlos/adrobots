# ТЗ: фронтенд создателя кампаний

## 1. Цель

Одностраничное React-приложение с формой из трёх полей. Пользователь
вводит название, выбирает страну и оффер, нажимает кнопку, видит
результат создания кампании в Keitaro. Вся логика создания живёт на
бэкенде, фронт только собирает данные и показывает результат.

## 2. Стек и сборка

- React 18, сборка Vite 5, язык TypeScript, роутинг react-router-dom 6.
- Без UI-библиотек и CSS-фреймворков, чистый CSS. Внешний вид по
  макетам: создатель по new_campaign_handoff (сетка #d9d9d9,
  светло-голубая кнопка), редактор в духе страницы Streams Keitaro.
- Фронт обращается только к нашему бэкенду. Ключ Keitaro и адрес
  Keitaro API во фронте не хранятся и в браузер не попадают.
- Адрес бэкенда: `VITE_API_URL`, по умолчанию http://localhost:8012.
  Прокси Vite не используется.
- Единственный адрес Keitaro во фронте: `VITE_KEITARO_URL` (по
  умолчанию https://tlgk.host), только для ссылки VIEW IN KT в
  редакторе.
- Все обращения к бэкенду собраны в двух модулях: `api.ts` (создатель)
  и `editorApi.ts` (редактор). Пути эндпойнтов задаёт бэкенд-часть ТЗ,
  во фронте они записаны только в этих модулях.
- Запуск и сборка фронта описываются в README.

## 3. Страница

Создатель (маршрут `/`): заголовок `New campaign`, под ним форма в
виде таблицы-сетки по макету. Редактор потоков (маршрут
`/campaigns/:keitaroId`) в исходное ТЗ не входил, описан в README.

## 4. Поля формы

### 4.1. Name

- Текстовое поле с подписью `Name`.

### 4.2. GEO

- Выпадающий список с подписью `Geo`.
- Список двухбуквенных кодов ISO 3166-1 alpha-2 фронт получает от
  бэкенда при открытии страницы, сам его не хранит.
- Опции показывают код как есть (DE, US, RU и так далее).
- Первая опция пустая, её текст `MX,AU,RO,...` (по макету). Пустую
  страну отклоняет бэкенд, блокировки на фронте нет.
- Выбирается ровно одна страна.

### 4.3. Offer

- Двухстрочное текстовое поле с подписью `Offer`, список офферов
  фронт получает от бэкенда при открытии страницы.
- Подсказки показываются как «ID название», не больше 20.
- Ввод в поле фильтрует список по ID и по названию.
- Оффер выбирается кликом по подсказке, при правке текста выбор
  сбрасывается. Блокировки отправки без выбора на фронте нет.
- На бэкенд уходит ID выбранного оффера.

## 5. Кнопка

- Кнопка с текстом `Create`, на всю ширину формы, светло-голубая.
- Недоступна, пока идёт запрос. Блокировки по незаполненным полям
  нет.
- На время запроса текст меняется на «Создаём...».
- Повторная отправка во время выполнения запроса невозможна ни кликом,
  ни нажатием Enter в поле.

## 6. Загрузка справочников

- Списки стран и офферов запрашиваются одновременно при открытии
  страницы.
- Если не загрузился хотя бы один список, под формой показывается
  текст ошибки от бэкенда, списки остаются пустыми. Для повторной
  загрузки страницу открывают заново.
- Индикатора загрузки нет, поля и кнопка доступны сразу.

## 7. Результат отправки

Бэкенд отвечает либо успехом, либо ошибкой. Фронт показывает ответ
под формой, не заменяя саму форму.

### 7.1. Успех

- Сообщение «Кампания создана: #ID название».
- Ссылка «Открыть редактор» на страницу редактора этой кампании.
- Форма остаётся заполненной, можно создать следующую кампанию,
  изменив поля.

### 7.2. Ошибка

- Под формой красным текстом показывается сообщение об ошибке.
- Текст берётся из ответа бэкенда. Ошибки Keitaro вида
  `{"поле": ["текст"]}` выводятся как `поле: текст`, а дубль названия
  или alias как «Кампания с таким названием уже существует».
- Если ответа бэкенда нет, показывается «Сервер недоступен».
- Значения полей формы при ошибке сохраняются.

## 8. Требования к ответам бэкенда

Фронт рассчитывает, что бэкенд вернёт:

- при успехе: ID кампании (`campaign_id`) и название (`name`);
- при ошибке: текст ошибки (`error`), показывается как сообщение;
  поле `step` фронт читает, но не показывает;
- для списка стран: массив кодов;
- для списка офферов: массив из ID и названия.

Точные пути и схемы фиксируются в бэкенд-части ТЗ.

## 9. Язык интерфейса

- Подсказки, сообщения об ошибках и статусы на русском.
- Заголовок, подписи полей и кнопка по макету: `New campaign`,
  `Name`, `Geo`, `Offer`, `Create`.

## 10. Поведение

- Форма отправляется по Enter в поле Name, пока кнопка доступна.
- В поле Offer Enter ничего не делает.
- Сообщения об ошибках и результат выводятся в одной области под
  формой.

## 11. Критерии готовности

- Страница открывается, списки стран и офферов загружаются.
- Во время запроса кнопка заблокирована, двойная отправка невозможна.
- При успехе показаны ID и название созданной кампании.
- При ошибке показан её текст, значения полей сохраняются.
- Ключ Keitaro нигде во фронте и в сетевых запросах браузера не
  встречается.
- Интерфейс соответствует макету new_campaign_handoff.
